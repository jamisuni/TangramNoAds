## Per-item results (the 10 points of the brief)

1. **Gate and scan.** `Feedback.on` is correct and complete. The scan is real: four rules, the Dialog deny, the build-declared globs, canaries that `error()`, and controls for every rule (comments, string literals, `::`, spacing). DA-128 cannot hide a real call (N2 explains why). Trace verified: `PlaySession.onEvent` → `SessionHost.build` wrapper → `AppViewModel` lambda → `Feedback.on` → `aids.sound/haptic` → outs. No other call site of `onEvent`. Gaps: N2.
2. **Lever.** `installProcessFlags()` is the first statement of `onCreate` (N8 for the order guard). All Compose paths named in DA-125 are covered; I confirmed this from the dex inventory, not from the design table. Counters are `AtomicInteger`s with saturation; everything runs on the main thread, so they are bounded and safe. No Dialog or Popup in release (grep above). V-08: S2, S3, DA-127 entry noted in S2.
3. **AudioTrack.** Design 3.3 items 1–7 are met: native rate with 48 000 fallback, one build thread, one volatile immutable map, `released` checked before each build, after the last and after publishing, `reloadStaticData` code counted, no focus, idempotent release. I traced the release-before-prepare interleavings by hand (release before the thread starts; during the build; between assignment and the recheck): no track outlives the instance and a double release is harmless. A play racing the build thread's post-publish release throws inside `runCatching`. The smoke test can fail (preflight, states, head advance asserted where an output exists, 20 + 20 cycles, fresh instance). `ViewHapticOut`: weak reference, no permission, follows the system setting; N3. Nits N4, N5.
4. **afterReset.** The no-persist invariant holds. `afterReset = showAt(indexState)` writes nothing; `persist()` captures `host.session`, which is already the new session. A stale `onChanged` from the discarded session goes through the host's current `persist` and saves the New board; the old `PlayArea`'s dispose path only calls `interruptDrag`, which does not call `settled()`. After a confirmed reset, an `onPause` save writes a New board. `confirmReset` is idempotent. `AfterResetTest` has real controls (index unchanged, no write, no capture, persist after reset still New). The one thing the fake host cannot model is the real discarded session, which I traced in the code instead.
5. **Debug / release split.** See the two lines above. The `DebugAids` twins have identical public signatures; `ReleaseSeparationTest` asserts the pass-through with controls. G-04: no "devtools" in `settings/src/main`, `app/src/main` or `app/src/release`.
6. **Overlay.** Input: `inputEnabled` is `rememberUpdatedState`; the `SideEffect` only runs three idempotent calls (`queue.clear()`, `machine.cancel()`, `interruptDrag()` which returns when idle). A late `Move` or `Up` after a cancel is a no-op in `GestureMachine` (`press`, `drag` null, `ignored` cleared). The overlay swallows touches by `pointerInput` ahead of the padding, and sits last in the Box. Focus: `focusProperties { onEnter = … }` precedes `.focusGroup()` (the required order), plus `clearFocus()` in a `LaunchedEffect` (see N1 for the keyboard side). `BackHandler`: settings is registered after the grid, so it wins; it clears a pending confirmation. Rotation: state is in the ViewModel and `rememberScrollState` is saveable. REQ-032 A1: opening is refused while dragging, so the interrupt in the `SideEffect` can only cancel a press that has not started a drag; nothing on the board changes.
7. **`play` events.** All nine emission points are before `settled()` and none is during construction or `restore`. The silent cases are right (refused turn or mirror, `interruptDrag`, `toProgress`). `setDragTurn` emits only when the turn changed. `PlayEventTableTest` covers each point, the silent ones and the order against `onChanged`. Mapping cannot throw (N9).
8. **Settings screen.** Read-modify-write is correct (`setSound` copies the freshly read settings; `SettingsControllerTest` proves a later timer write survives). `confirmReset` is gated by `confirmingReset` and clears it first. The ⚙ is `drawLine` / `drawCircle` in px, no scale, no path; `PxDrawingScanTest` has controls. Every control has a 48 dp minimum. The English REQ-009 and REQ-049 strings equal the locked text character for character (I compared them with the REQ files). The Finnish texts equal F14. 13 keys in both files. Keep is first, Erase second. S1 is the only problem here.
9. **Moved-in JVM tests.** No tautologies except the one caveat in N6. `FeedbackGateTest` has its positive control (on → exactly one sound, one tick only for LOCK) and a flip-between-events case. `SoundSynthTest`, `LockedTextsTest` and `PxDrawingScanTest` have control cases that can fail. Tokens appear only in the three covering classes (grep). `FeedbackMappingTest` is real. `PromiseSourceScanTest` gains the `Vibrator` names and the `VIBRATE` manifest read.
10. **Staged T7a kit.** `Seed.reach` fails loudly and never taps Erase. `ResetStoreRule` wipes the store before and after every test, so a sound switch left off by a failed C7 run cannot leak (the C7 test switches it back on in the middle, not in a `finally`, but the wipe covers it). The C7 test has its positive control (the LOCK request and the tick with sound on) before the off-run. C10's rotation is restored in a `finally` through the existing `Rotation` helper. `AirplaneModeAppTest` restores airplane mode in `@After`. N1 is the only issue.
