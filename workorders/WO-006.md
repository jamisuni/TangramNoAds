# WO-006 — #Layout, #Language, #Promise: every screen on phones and tablets, in two languages, free

**Status:** **Closed 2026-10-04** (G3 passed — governance row 7 = ai; checkpoint 6 surfaced to Jami)  ·  **Mode:** Full
**Kicked off by:** Jami / 2026-10-02 ("continue with all reqs"; `build-map.md` §2, governance row 8), opened by the AI right after the WO-005 close (2026-10-04)  ·  **Plan approved:** 2026-10-04 by the AI under row 7, after plan review spot-check "forward" (`tasks.md` v1.8 + E1–E5)

## Goal

Make the game right on every screen it runs on. A phone in portrait shows all seven tray pieces
without scrolling and keeps the tray clear of the gesture bar. A tablet in either orientation
keeps the tray in one row and keeps every placed piece when rotated. Every player control can be
touched comfortably. The app speaks Finnish on a Finnish device and English everywhere else. On
every screen there is still nothing to pay, no ad and no network, so the game is free and offline.

## Scope  *(the traceability anchor — build-map.md §2, WO-006 row)*

- **Implements:**
  - **#Layout** (code home `app`): REQ-006 A1, REQ-035 A1–A2, REQ-036 A1–A2, REQ-037 A1, and TYPE-007 (the layout class, kernel). The minimal shell is from WO-003: edge-to-edge, the portrait policy F3 and the tray rows.
  - **#Language** (code home `app`; strings live in every module, G-05): REQ-047 A1–A2.
  - **#Promise** (system level; verified at app and release level, G-01, V-01): REQ-001 A1, REQ-008 A1–A2, REQ-010 A1–A2.
- **Carried OUT:**
  - → WO-009: REQ-001 A2 (store labels).
  - Any on-screen part that needs a later WO's screen, for example the settings screen in REQ-047 A1 and in REQ-001 / REQ-008 "every screen" (settings arrive in WO-007). The design names each carried part, and it is re-verified with the same token in that WO (architecture.md §5).
- **Governed interfaces touched:** none expected. `IPuzzleLibrary` (locked) and `IProgressStore` (notify) are only consumed. The v1 save format is frozen (LOCK-V1), so rotation must keep placed pieces without a format change.
- **Out of scope:** settings (WO-007), play time and best times (WO-008), store listing and release checklist (WO-009).

## Mode justification

Chosen: **Full**. This WO touches several modules (the `app` shell, `play` layout, `browse`, strings in every module) and the
device configurations (phone, two tablet orientations, rotation, gesture navigation, locale, airplane mode). The design
choices (how tablets and rotation are verified, how the layout class flows) are not obvious.

## Constraints & notes

- **Device channels (AGENTS.md):** JVM, plus device tests on `Medium_Phone_API_37.0` **and** `Phone_API_26`
  (Android 8.0, the minSdk floor), one emulator at a time. A tablet channel, if the design needs one, is a
  hand-made AVD, because there is no avdmanager; see DA-93 for how `Phone_API_26` was made.
- **Drawing rule (DA-92):** `play` draws every path in px; never draw a path under a canvas scale.
- **Lessons (AGENTS.md):**
  - every frozen seam names its delivering task;
  - test adapters fail loudly;
  - Compose UI-test imports;
  - compile staged and held-out tests early;
  - UI and device tasks run on sonnet, and the orchestrator reads their diffs;
  - release safety (V-04 + `--positive-control`) and two device channels at the close.
- **Strings:** V-05 string parity; AI-written Finnish goes on the owner's review list.
