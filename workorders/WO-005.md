# WO-005 — #DevTools: the debug-only solution reveal

**Status:** In progress (G3 passed — governance row 7 = ai)  ·  **Mode:** Full
**Kicked off by:** Jami / 2026-10-02 ("continue with all reqs"; `build-map.md` §2, governance row 8), opened by the AI right after the WO-004 close (2026-10-03)  ·  **Plan approved:** 2026-10-03 by the AI under row 7, after plan review spot-check "forward" (`tasks.md` v1.5)

## Goal

Let the owner check that every puzzle really can be solved, on a debug build. A DEV button on the
board asks for the passcode 0417. After the right passcode it can show each piece's solution
position, or solve the current puzzle at once. None of this may exist in a release build.

## Scope  *(the traceability anchor — build-map.md §2, WO-005 row)*

- **Implements:** #DevTools (code home `devtools`, an Android library, debug only), covering
  **REQ-046 A1–A4**. For A3, "no best time" is checked at event level (`byAid`), because best
  times arrive in WO-008.
- **Verifier V-04** (architecture.md G-04): it builds the release APK, unzips it, and scans the dex
  and resources for `…tangram.devtools` classes and the passcode literal. The WO-003
  `tools/check_apk_puzzles.py` is folded into V-04 (build-map §2, carried from WO-003).
- **Carried OUT:** → WO-008, the aid-solve regression on real best times (REQ-030 rule,
  REQ-046 A3).
- **Governed interfaces touched:** `IPuzzleLibrary` (consumed; locked) · `IProgressStore` (notify;
  the aid-solve must record Solved without a best time — check against the frozen v1 format,
  which must NOT change: LOCK-V1).
- **Out of scope:** best-time display (WO-008), settings (WO-007).

## Mode justification

Chosen: **Full**. G-04 is a release-safety guardrail (rule 11), a new module and source-set
split are involved (ADR-006), and V-04 must be able to fail.

## Constraints & notes

- **G-04 / ADR-006:** DevTools live only in the debug variant. `app` reaches them through a
  neutral hook (no `devtools` class name or passcode in `main`). V-04 proves the release APK is
  clean, and its self-test must show it can fail.
- **The v1 save format is frozen (LOCK-V1).** The aid-solve stores Solved with a null best time,
  which the v1 format already carries (CR-2 confirmed). Any format change is a hard-stop.
- **Verification channels:** JVM, plus device tests on `Medium_Phone_API_37.0`; the API 26 launch
  is still waived (DA-43).
- **Lessons (AGENTS.md):**
  - every frozen seam names its delivering task;
  - test adapters fail loudly and map through public seams;
  - Compose UI-test imports;
  - UI and device tasks run on sonnet, and the orchestrator reads the diffs.
